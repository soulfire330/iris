# ADR-0005: Диаризация участников — дорожки TrackEgress вместо модели-диаризатора

## Контекст

Сводки (ADR-0004) собираются из транскрипта единого микса комнаты (RoomComposite,
ADR-0002): STT получает один файл, «кто говорил» не известно. Нужна атрибуция
реплик по участникам (и попутно — более чистое распознавание: каждая дорожка
без кросс-помех микса).

Отдельная модель-диаризатор (pyannote и т.п.) отвергнута: это новый сервис с GPU,
а метки «SPEAKER_00» всё равно пришлось бы сопоставлять с участниками. STT-сервер
(GigaAM, OpenAI-совместимый враппер) менять нельзя — он внешний. Старые записи
(единый микс) не перерабатываем.

## Решение

- **Запись дорожек на участника**: при старте записи бэкенд, кроме микса
  (RoomComposite, как в ADR-0002), запускает по `TrackEgress` на каждого
  участника с аудио-треком → `{имя}-{логин}.ogg` (Opus; повторный вход —
  `-2.ogg`). Дорожки пишутся всегда, не только при заказе сводки: кнопка AI
  нажимается в середине встречи, «отмотать» аудио назад нельзя.
- **Опоздавшие**: фоновый поллер (10 с) догоняет дорожки участникам, которых не
  было на старте; TrackEgress сам завершается, когда участник выходит.
- **Манифест `{имя}.tracks.json`** (пишет бэкенд, источник правды, переживает
  рестарты): файл, логин, отображаемое имя (Employee-маппинг), `started_at`
  дорожки и `track_sid` (дедуп). Секретарь остаётся без конфига: сдвиг времени
  и имена он берёт отсюда.
- **Стоп**: останавливаются все активные egress комнаты (микс + дорожки);
  иначе TrackEgress жил бы до выхода участников.
- **Секретарь**: если манифест есть — каждая дорожка распознаётся отдельно
  (`response_format=verbose_json`, сегменты с таймкодами), сегменты сдвигаются
  на старт дорожки относительно начала встречи и склеиваются хронологически в
  размеченный транскрипт `[ММ:СС] Имя: реплика`. Манифеста нет — старый путь,
  файл целиком.
- **Кэш дорожек** — распознанные сегменты сохраняются в `summary.json`
  (`tracks`): ретрай не перегоняет STT для готовых дорожек. Параллельность STT —
  пул 3 (не утопить GPU STT-сервера).
- **В LLM** транскрипт уходит одним user-сообщением в виде размеченного текста
  (тот же формат, что хранится в summary.json): структура сводки не требует
  ссылок на время, отдельная JSON-схема добавила бы токены без пользы.

## Следствия

- Транскрипт — хронологический, с именами; микс для воспроизведения не меняется,
  веб не затрагивается (дорожки `.ogg` не попадают в список записей — он читает
  только `*.mp4`).
- Старые записи без манифеста разбираются как раньше; перегонять их через
  диаризацию не планируется.
- Точность таймлайна ~1–2 с (задержка старта захвата egress) — для сводки
  достаточно.
- Дорожки хранятся всегда (Q5): если место станет проблемой — добавить
  авто-очистку.
